# のむしょう

毎朝 7:00(JST)に、総合+テックのニュース10件を Claude で要約し、Discord に投稿する Bot です。
GitHub Actions の cron が実行し、Discord Webhook へ投稿します(常駐サーバー不要)。

処理の流れ: RSS 取得 → 重複除外 → 総合/テックで10件選定 → Claude で一括要約 → Embed に整形 → Webhook で投稿。
各記事は「見出し + 1〜2行の要約 + 元記事リンク」です。

## 初回セットアップ チェックリスト

1. Discord で Webhook を作成し、URL を控える(下記「1」)。
2. [Anthropic Console](https://console.anthropic.com/) で API キーを用意する。
3. GitHub Secrets に `DISCORD_WEBHOOK_URL` と `ANTHROPIC_API_KEY` を登録する(下記「2」)。
4. Actions から `dry_run=true` で手動実行し、緑になりログに本文が出ることを確認する。
5. `dry_run=false` で手動実行し、Discord に届くことを確認する。
6. 翌朝の cron 実行を待つ(数分〜数十分遅れることがある)。

### 1. Discord で Webhook を作成する

1. 投稿先サーバーで、対象チャンネルの「チャンネルの編集」(歯車アイコン)を開く。
2. 「連携サービス」→「ウェブフック」→「新しいウェブフック」を選ぶ。
3. 「ウェブフックURLをコピー」でURLを控える。
4. このURLは秘密情報です(知っている人は誰でも投稿できます)。コードやコミットに含めないでください。

※ 作成にはチャンネルの管理権限が必要です。画面の表記は変わることがあります。

### 2. GitHub Secrets に登録する

1. リポジトリの「Settings」→「Secrets and variables」→「Actions」を開く。
2. 「New repository secret」で次の2つを登録する。

| Secret | 内容 |
|---|---|
| `DISCORD_WEBHOOK_URL` | 手順1でコピーした Webhook URL |
| `ANTHROPIC_API_KEY` | 要約に使う Anthropic API キー |

### 3. Actions で手動実行する

1. 「Actions」タブで左の一覧から `daily-news` を選ぶ。
2. 「Run workflow」を押し、`dry_run` を選んで実行する。
   - `true`: 投稿せず、ログに投稿内容(JSON)を出力するだけ。Webhook は不要だが、RSS 取得と要約 API 呼び出しは実際に行われる。
   - `false`(既定): Discord に実際に投稿する。

定期実行は cron `0 22 * * *`(22:00 UTC = 07:00 JST)で、実投稿(`dry_run` なし)です。

## ローカルで実行する

Python 3.11 以上が必要です。

1. 仮想環境を作って有効化する。
   ```sh
   python3 -m venv .venv
   source .venv/bin/activate
   ```
2. 開発用依存込みでインストールする。
   ```sh
   pip install -e '.[dev]'
   ```
3. dry-run で実行する(`--dry-run` 時は Secrets 不要。投稿せず標準出力に表示)。
   ```sh
   python -m nomusyo.main --dry-run
   ```
   - `ANTHROPIC_API_KEY` を環境変数に渡さない場合、要約はスキップされ「見出し+リンク」のフォールバック表示になる。要約も試すなら `ANTHROPIC_API_KEY='<キー>'` を付ける(API 利用料がかかる)。
   - `DRY_RUN=true` を環境変数で指定しても同じ。
4. 実際に投稿する場合は両方の Secret を環境変数で渡す。
   ```sh
   DISCORD_WEBHOOK_URL='<URL>' ANTHROPIC_API_KEY='<キー>' python -m nomusyo.main
   ```

テストと Lint: `pytest` / `ruff check .`

## 設定(環境変数)

`src/nomusyo/config.py` で読み込まれるものです。Actions で変える場合は `.github/workflows/daily-news.yml` の `env:` に追記します(現状のワークフローは Secrets と `DRY_RUN` のみ渡しています)。

| 変数 | 既定値 | 説明 |
|---|---|---|
| `DISCORD_WEBHOOK_URL` | なし | 投稿先 Webhook。dry-run 以外で必須 |
| `ANTHROPIC_API_KEY` | なし | 要約用 API キー。dry-run 以外で必須 |
| `SUMMARY_MODEL` | `claude-haiku-5-5` | 要約モデル(空文字なら既定値) |
| `NEWS_TOTAL_COUNT` | `10` | 総件数(1以上の整数) |
| `NEWS_GENERAL_RATIO` | `0.5` | 総合の比率(0〜1)。総合枠は `floor(件数×比率+0.5)`、残りがテック |
| `NEWS_MAX_AGE_HOURS` | `36` | これより古い記事は除外(1以上の整数) |
| `DRY_RUN` | `false` | `true`/`1`/`yes`/`on` で投稿せず出力のみ |
| `LOG_LEVEL` | `INFO` | ログレベル |

> **注意:** 既定モデル ID `claude-haiku-5-5` が実在するかは、初回の手動実行で確認してください(存在しない場合、要約は失敗し実行が exit 1 になります)。

## 動作仕様

### ニュースソース(`src/nomusyo/core/sources.py`)

| ジャンル | ソース |
|---|---|
| 総合 | NHKニュース 主要 / 社会 / 政治 / 経済 |
| テック | ITmedia NEWS / Publickey / GIGAZINE / Zenn トレンド / はてなブックマーク IT / Hacker News |

リストの順が優先順で、重複する記事は先に載っているソースが残ります。

### 選定・配分

1. 各ソースから最大20件を取得し、`NEWS_MAX_AGE_HOURS` より古い記事を除く。
2. URL とタイトルの類似で重複を除く(同一実行内のみ)。
3. 総合/テックを `NEWS_GENERAL_RATIO` で配分(既定 5件/5件)。ジャンル内はソース間のラウンドロビンで、1ソース最大3件。
4. 片方が足りなければ他方で補填する(補填時は1ソースの上限を緩める)。

### 要約と投稿

- 1回の API 呼び出しで全件を日本語要約(見出し40字・要約120字以内)。記事内容は「データ」として扱い、リンクは LLM ではなくフィード由来のものを付与。
- 投稿は1記事=1 Embed。Embed 数・文字数の上限を超える場合は複数メッセージに分割。メンションは無効化。

### 失敗時の挙動と終了コード

| 事象 | 挙動 | 終了コード |
|---|---|---|
| 一部ソースの取得失敗 | 警告ログのみで続行 | 0 |
| 要約の一時的な失敗(429/5xx/タイムアウト/出力不正) | 1回再試行。それでも駄目な記事は「見出し+リンク+RSS概要の先頭80字」で投稿し、本文に注記を付ける | 0 |
| 恒久的な API エラー(キー無効・権限なし・モデル不存在・不正リクエスト) | 再試行せず、フォールバック表示で投稿した上で失敗扱い | **1** |
| 記事が0件(全ソース失敗/全て古い) | 投稿しない | **1** |
| 設定エラー(必須 Secret 未設定、値が不正) | 投稿しない | **1** |
| Webhook 失敗(リトライ後) | 分割送信の途中なら送信済み分は再送しない | **1** |

exit 1 になると Actions の実行が失敗し、GitHub の通知(メール等)で気付けます。Webhook URL と API キーはログに出ません。

## 常駐 Bot(Discord コマンド)

予定・TODO・朝のダイジェストを扱う常駐 Bot を `src/nomusyo/bot/` に実装しています。セットアップ(招待、`.env`、Docker)と運用は [docs/operations.md](docs/operations.md) の「常駐 Bot の運用」を参照してください。

- `ALLOWED_USER_IDS` に含まれるユーザーだけが操作できます。応答は本人にのみ見えます(ephemeral)。
- 想定は個人用です。複数人を許可すると、全員が先頭ユーザー(owner)の予定・TODO・設定を操作できます。

### コマンド一覧

| コマンド | 内容 |
|---|---|
| `/news` | 今日のニュースを要約して、実行したチャンネルに投稿します。連続実行は 300 秒のクールダウン |
| `/status` | 稼働時間、バージョン、Gateway 遅延、参加サーバー数を表示 |
| `/add` | 予定を登録。保存前にプレビューを出し、「保存 / 修正 / キャンセル」で確定。引数は日時・タイトル・所要時間・場所・メモ・リマインド |
| `/list` | 予定一覧。期間は `today` / `week`(既定)/ `month` / `all`、検索語 `query` で絞り込み。ページ送り可 |
| `/edit` | 予定を編集(候補から選択し、入力フォームで変更) |
| `/delete` | 予定を削除(確認ボタンで確定。論理削除) |
| `/todo add` | TODO を追加。期限・メモ・優先度(0〜3)・リマインド(期限が必要) |
| `/todo list` | TODO 一覧。状態は `open`(既定)/ `overdue` / `done` / `no_due` / `all` |
| `/todo done` | TODO を完了(候補から選択) |
| `/todo delete` | TODO を削除(確認あり) |
| `/today` | 今日の予定と TODO |
| `/week` | 今後 7 日間の予定と TODO |
| `/settings` | ダイジェスト時刻、空の日のスキップ、既定リマインド、通知チャンネル、DM 通知の表示と変更 |

入力例:
- 日時: `2026-11-03 15:00` / `11/3 15:00` / `明日 9:00`。日付だけ(`11/3`)は終日予定。
- 所要時間: `90m` / `2h` / `1h30m` / `1d`
- リマインド: `10m,1h,1d@20:00`(カンマ区切り)

### 朝のダイジェスト

1. 既定は 06:55(JST)。今日の予定と TODO を 1 日 1 回、通知チャンネルに投稿します。ニュースとは別の投稿です。
2. 時刻は環境変数 `DIGEST_TIME` で既定値を決め、`/settings` の「ダイジェスト時刻」で変更できます。変更は次の判定から反映されます。
3. 予定や TODO がない日も、既定では投稿します。`/settings` の「予定なしの日はダイジェストを出さない」をオンにすると投稿しません。
4. 指定時刻から 3 時間を過ぎて Bot が動き出した場合、その日の分はスキップし、管理者に DM で知らせます。
5. 投稿先は `/settings` の通知チャンネルです。未設定の場合は `NOTIFY_CHANNEL_ID` を使います。

### 未対応の機能

- **繰り返し予定**: 内部では RRULE の展開(毎日・毎週・毎月・平日・第N曜日)に対応していますが、Discord からは登録できません(V2-60 以降)。`/add` は単発の予定だけを登録します。
- **リマインドの通知**: `/add`・`/todo add` の `remind` と `/settings` の既定リマインドは保存のみです。**通知はまだ送信されません**(V2-52〜V2-58 で実装予定)。
- **祝日**: `/today` `/week` とダイジェストに祝日は出ません(V2-62)。
- **DM 通知**: `/settings` で設定は保存されますが、DM への送信は未実装です。
- **定時ニュース**: まだ Bot からは投稿していません。毎朝の投稿は上記の Actions の cron が担当します(V2-70〜V2-72 で移行予定)。

## 将来の拡張と、現状やっていないこと

- 常駐 Bot 化: 進行中です。`bot/` にスラッシュコマンド、予定・TODO、朝のダイジェストを実装済みです(上記「常駐 Bot」)。`core/` は Discord 非依存で、`run_pipeline(config)` を `/news` から呼んでいます。定時ニュースの Bot 移行は未実装で、移行時は Actions の cron を止めて二重投稿を防ぐ必要があります。
- 日跨ぎの重複防止はしていません(重複除外は同一実行内のみ。前日と同じ記事が `NEWS_MAX_AGE_HOURS` 内に残っていれば再び載り得ます)。
- Hacker News のテック枠での上限はありません(1ソース最大3件の制限のみ)。
- メッセージ分割はジャンル境界ではなく、Embed 数・文字数の上限で行います。
- 10件の選定は「新しい順+ラウンドロビン」で、LLM による重要度選定はしていません。
